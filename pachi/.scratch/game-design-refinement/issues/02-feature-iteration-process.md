## Question

How should the feature ideation and iteration process in `docs/design/process.md` be structured (including a standardized proposal template, Vision reconciliation checklist, MDA mapping, and 3P playtestable Hypotheses of Fun) to prevent design drift?

## Answer

Created `docs/design/process.md` establishing:
1. **4-Stage Feature Lifecycle**: Pitch & Vision Check $\rightarrow$ Hypothesis & Spec $\rightarrow$ Playtest & Verification $\rightarrow$ Production Integration.
2. **Four-Pillar Scorecard**: Mandatory advance of $\ge 1$ pillar (Pachinko, Incremental, Deckbuilder) with a strict non-violation check on Simplicity (zero micromanagement).
3. **3P Hypothesis of Fun Formula**: `Action + Aesthetic Emotion + Dynamic Mechanism + Verification Indicator`.
4. **Tiered Prototyping**: Tier 1 Sandbox Scenes for components/physics; Tier 2 Debug feature flags/command palette menu in main loop for systems/economy.
5. **Standardized Proposal Template**: Markdown template in `.scratch/<feature-slug>/spec.md`.
